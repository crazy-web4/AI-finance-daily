## 任务定义

- **文档来源**:`资深架构师优化建议_第11批_单体深化.md` §三 T-A2
- **目标**:配置一次,每天固定时间自动出报;用户不需要懂 launchd/crontab
- **现状**:"每天自动跑"只能靠用户手工配 cron/launchd,代码里无任何调度能力,`doctor` 只会提示"检查 cron / launchd"
- **落地后**:
  - `ai-daily schedule enable --at 07:30 --mode full` 生成并安装 launchd plist / crontab
  - `ai-daily schedule status` 显示下次执行时间、上次执行结果
  - `ai-daily schedule disable` 卸载
  - `ai-daily schedule test` 立即试跑一次(不装)

## 落地步骤

1. **`config/schedule.yaml`**:默认 `{enabled: false, at: "07:30", mode: full, args: [], log_dir: logs}`;读写用标准库 yaml(项目已有 pyyaml)
2. **`plist.py`**:根据 at 时间生成 `com.aidaily.run.plist`(`StartCalendarInterval` Hour/Minute、`ProgramArguments` 指向 `ai-daily run --mode 对应`,WorkingDirectory=项目根、StandardOut/ErrPath=logs);写入 `~/Library/LaunchAgents/`,`launchctl load`(macOS 特有,非 macOS 时返回"仅支持 macOS,请用 crontab")
3. **`crontab.py`**:生成 `30 7 * * * cd <项目根> && <python> run_daily.py --full >> logs/cron.log 2>&1` 行;通过 `crontab -l` 合并写入(保留已有行)
4. **`status`**:读 schedule.yaml + 检查 launchctl list / crontab -l 是否存在 + 最近 runlog 结果,输出"下次执行时间/上次成功或失败"
5. **`test`**:不安装,直接调 `run_daily.py --test` 验证被调度命令可跑
6. **平台探测**:`sys.platform == "darwin"` 走 launchd,否则 crontab;都不可用时给出明确提示
7. **测试**(≥5 个):plist 内容(StartCalendarInterval 正确)、crontab 行格式、enable 幂等、disable 幂等、status 三态(无任务/已装/上次失败)、config 读写不破坏注释
8. **commit**:`feat(T11-A2): 内置定时调度`
